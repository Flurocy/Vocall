# 回收站实现计划（软删除 + 还原 + 独立导航页）

日期：2026-07-28
分支：feat/v1-popup-tray，BASE 32f75ef（hotkey 单键调整完成态）
背景：用户后续功能顺序 ②（回收站）。用户决策：定位=**防误删**；入口=**独立导航页**（左侧导航加"回收站"，与生词库/词书/设置同级）。

## 用户决策（已确认）
- **定位：防误删**。删除=软删除（进回收站，可还原）；非"暂不背的收纳区"。
- **入口：独立导航页**。App.tsx tab 加 `'trash'`，左侧 nav 加「回收站」按钮，右侧渲染 TrashView。
- **保留策略**：MVP 永久保留 + 手动「清空回收站」+ 单条「彻底删除」。自动清理（如30天）放 backlog（词不多，用户自评不会到大量级）。

## 设计取舍（实现者逐字遵守）
- **包装式软删除（方案B，非加字段）**：store schema 加独立 `trash: { item: VocabItem; deletedAt: number }[]`。删除=把 VocabItem 从 vocab 移到 trash（包装 deletedAt）；**不动 VocabItem 结构**（已在 vocab.ts+ipc-types.ts 两处定义，加字段要改两处+迁移，成本高）。srsState 保留不动（按 id 索引，还原时自然恢复）。
- **还原语义**：从 trash 取出 item 放回 vocab。status+SRS 完全保持删除前的样（srsState 没动、item 完整）。还原后 duePop 可能"过期"（< popCount 立即到期优先弹）——合理，防误删就该继续背。
- **getDueVocab/listVocab 天然不查 trash**（只遍历 vocab 数组），trash 词不会被弹/列出，无需额外过滤。

## 全局约束（精确值，子代理逐字遵守）

1. **store schema** 加 `trash: { item: VocabItem; deletedAt: number }[]`。defaults 和 `_resetStoreForTests` 的 mem 都加 `trash: []`。
2. **deleteVocab(id) 改为软删除**：从 vocab 移除该词 → push `{ item, deletedAt: Date.now() }` 到 trash。srsState 不删（保留供还原）。
3. **新增函数**（store.ts 或 vocab.ts，看现有 deleteVocab 在哪）：
   - `listTrash(): { item: VocabItem; deletedAt: number }[]`：返回 trash，按 deletedAt 倒序（最近删的在上）。
   - `restoreVocab(id)`：从 trash 找到该 id 的包装 → 取 item 放回 vocab → 从 trash 移除。srsState 不动（自然恢复）。
   - `purgeVocab(id)`：从 trash 真删该条 + `deleteSrsState(id)`（彻底删除，srsState 也清）。
   - `clearTrash()`：清空 trash 全部 + 删所有 trash 词的 srsState。
4. **IPC**（ipc.ts）：`vocab:listTrash` / `vocab:restore` / `vocab:purge` / `vocab:clearTrash`，错误统一抛（与现有风格一致，本地无外部攻击面）。
5. **preload + TasymizeApi**：暴露 `listTrash() / restore(id) / purge(id) / clearTrash()`，签名加到 ipc-types.ts 的 TasymizeApi。listTrash 返回类型 `{ item: VocabItem; deletedAt: number }[]`（可抽个 TrashEntry 类型）。
6. **前端 App.tsx**：tab 类型加 `'trash'`；nav 加「回收站」按钮（trash 图标/文字均可，跟现有三个按钮同款 navBtn 样式）；main 渲染 `<TrashView theme={theme} />`。
7. **TrashView.tsx（新组件）**：
   - 列表：每条显示 word/meaning/status 徽标（复用 ExpressionsView 的 statusBadge 风格）+ 删除时间（deletedAt 格式化，如"2 小时前"或日期）。
   - 每条「还原」「彻底删除」两个操作（group-hover 显示，同 ExpressionsView row 模式）。
   - 顶部「清空回收站」按钮（带 confirm，彻底删除不可恢复）。
   - 空态："回收站是空的"。
   - 操作后 reload 列表。
8. **ExpressionsView 文案修正**：批量删除的 confirm 文案「此操作不可撤销」→ 改为「移到回收站，可还原」（因为现在 deleteVocab 是软删除）。单条删除无需 confirm（原本就没）。
9. **迁移**：旧数据无 trash 键，store defaults `trash: []` 兜底，mem 初始化也加。无需专门 migrate 函数（defaults 自动补）。但 _resetStoreForTests 的 mem 字面量要加 trash: []，否则测试读 trash 报 undefined。
10. **不动**：scheduler.ts、hotkey.ts、popup.ts、engine.ts、VocabItem 结构、srs.ts。

## 包划分

### 包1 后端（软删除 + 还原/清空，TDD）
文件：`src/main/store.ts`、`src/main/vocab.ts`、`src/main/ipc.ts`、`src/preload/index.ts`、`src/shared/ipc-types.ts`、`tests/`

1. store.ts：schema 加 trash；defaults + mem 加 trash: []；read/write 复用现有；export trashBox 或直接在 vocab.ts 操作。
2. vocab.ts：deleteVocab 改软删除；新增 listTrash/restoreVocab/purgeVocab/clearTrash。
3. ipc.ts：4 个 handler。
4. preload + ipc-types：暴露 + 签名。
5. TDD 测试（tests/trash.test.ts）：
   - deleteVocab：词从 vocab 消失、进 trash（带 deletedAt）、srsState 仍在。
   - listTrash：倒序。
   - restoreVocab：词回 vocab、trash 移除、status/srs 保持。
   - purgeVocab：trash 真删 + srsState 删。
   - clearTrash：全清 + 对应 srsState 全删。
   - 边界：restore/purge 不存在的 id（no-op 不崩）；clearTrash 空回收站（no-op）。
6. `npm test` 绿 + `npm run build` 过。

### 包2 前端（导航 + TrashView + 文案）
文件：`src/renderer/manager/App.tsx`、`src/renderer/manager/views/TrashView.tsx`（新）、`src/renderer/manager/views/ExpressionsView.tsx`（仅文案）

1. App.tsx：tab 加 'trash' + nav 按钮 + main 渲染 TrashView。
2. TrashView.tsx：列表 + 还原/彻底删除/清空 + 空态，复用 theme 类 + 零古风。
3. ExpressionsView.tsx：批量删除 confirm 文案改"移到回收站，可还原"。
