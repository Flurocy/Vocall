## 0. 一句话概述

**Tasymize 是一个 Windows 桌面悬浮弹窗工具：在你使用电脑（打游戏、看视频、刷网页）的间隙，偶尔弹出一张「雅思高级表达」卡片，配合音效与"先问后答"的交互，帮你在无负担的被动场景中积累冲刺 7 分所需的词汇与语法表达。**

---

## 1. 背景与用户画像

### 1.1 使用者

- **唯一用户：项目作者本人**（纯个人自用工具，不商业化、不面向大众）。
- 因此**不需要差异化竞争**，唯一标准是"对我本人好用"；市面上已有产品（DesktopVoc、弹幕单词、ToastFish 等）仅作交互参考。

### 1.2 用户目标

- 备考 **雅思 A 类（学术类）机考**，目标 **7+**，当前自估 **5.5**（自评只低不高）。
- 自我诊断的短板：**高级词汇量、语法**——这两项正是雅思写作/口语四大评分标准中 LR（词汇）与 GRA（语法）的核心，也是 5.5→7 的主要瓶颈。

### 1.3 核心痛点（决定产品形态的关键认知）

- **用户明确不可能"打开一个学习软件对着学"**。
- 需要的是**融入日常、被动吸收**：在玩游戏、看视频、刷网页的过程中"顺带"学到。
- 市面上现成产品不符合个人习惯，故自建。

---

## 2. 产品形态与核心原则

### 2.1 形态

**偶尔弹出的小悬浮窗**（不是一直显示、不是滚动轮播）。在屏幕边角弹出，停留片刻后消失，弹出时配音效。

> 用户特别说明：这是对 DesktopVoc 产品形式的个人化修正——他想要的不是"常驻滚动条"，而是"**偶尔弹出的提醒式卡片**"。

### 2.2 三条不可违背的设计原则

1. **绝不强迫**——用户不点、不看也完全 OK，弹窗自动消失，零负担。所有交互都是"加分项"而非"门槛"。
2. **好看是刚需**——UI 必须精美（毛玻璃质感、好的字体/配色/排版）。丑的东西挂在屏幕上会被嫌弃、被关掉，产品就失败了。
3. **内容提分导向**——不做孤立背单词，只做"**普通词 → 雅思高级表达**"的可直接用于写作/口语的表达块，确保提分相关性。

## 3. 功能范围（四个模块）

| 模块 | 说明 | 版本 |
|------|------|------|
| **① 弹窗背词**（核心） | 按记忆曲线在屏幕边角弹出表达卡片，先问后答 + 自评按钮 | **V1** |
| **② 生词库 / 表达库** | 本地存储全部表达块及其掌握状态，可查看/管理 | **V1** |
| **③ 截图单词翻译** | 全局快捷键触发截图 → OCR 识别图片中单词 → AI 翻译讲解 | V2 |
| **④ 句子升级** | 手动输入一句话 → AI 以"建议"形式给出更高级表达（原句尚可时只给建议不强行改） | V2 |

> **分期原则**：自用 + 练手项目，先把核心闭环（①+②）跑通，再叠加 AI 功能（③④）。避免一口气全做导致烂尾。

### 3.1 V1 范围（本次实现目标）

一个 Electron 桌面应用：
- 本地内置/可编辑的表达块库（SQLite 存储）。
- 按间隔重复（SRS）调度，在屏幕边角弹出卡片。
- 卡片交互：音效提示 → 先显示"普通词"（给几秒回想）→ 翻出"高级表达" → 底部三个自评按钮（`忘了`/`有点印象`/`记得`）。
- 点击按钮后按评分调度下次出现；**不点击则几秒后自动消失**（视为一次纯曝光）。
- 一个最小管理界面：查看/新增/编辑/删除表达块，查看掌握情况，基础设置（弹出间隔、停留时长、音效开关、音量）。

### 3.2 V2 范围（预留接口，本次不实现）

- 全局快捷键截图翻译（OCR + AI）。
- 句子升级面板（AI 建议）。
- AI 配置：自带 API Key，支持 **DeepSeek / Kimi** 可切换（配置面板预留多 provider 切换）。

> V1 阶段即把 **AI 配置的数据结构与设置项**预留好（provider、apiKey、baseUrl、model），保证 V2 平滑接入。

## 4. 核心交互详细设计（V1 的"弹窗背词"）

### 4.1 一次弹出的完整生命周期

```
（到点）触发调度
   → 屏幕边角弹出卡片（半透明毛玻璃、圆角、阴影，滑入动画）
   → 播放提示音效（轻"叮"，音量可调）
   → 【阶段A·回忆】先只显示"普通词"（如 important），停留 N 秒让用户回想
   → 【阶段B·揭晓】翻出"高级表达"（如 plays a pivotal role in …）+ 一句雅思语境例句
   → 底部浮现三个自评按钮：😵 忘了  /  🤔 有点印象  /  😎 记得
   → 用户点击其一：
        · 记录评分 → 计算下次出现时间（SRS）→ 卡片淡出消失
     用户超时未点（M 秒）：
        · 视为"纯曝光"，不改变（或轻微改变）调度 → 卡片自动淡出
```

### 4.2 "如何让我更好背下单词"的机制（记忆科学应用）

这是参考主流背词方法后的核心设计，也是本项目区别于"纯展示"的关键：

| 机制 | 原理 | 在本项目的落地 |
|------|------|----------------|
| **主动回忆（测试效应）** | 先提问再揭晓，记忆强度远超直接给答案 | 阶段A 先显示"普通词"逼你回想，再揭晓"高级表达" |
| **间隔重复（SRS）** | 在"快要忘记"的时刻重现，长期记忆最优 | 用 SM-2 变体按自评评分计算下次弹出时间 |
| **多感官编码** | 听觉线索增强编码 | 弹出音效（可自定义音频文件） |
| **低压力曝光（次级效应）** | 不点也有"纯曝光"收益 | 超时自动消失，无惩罚、无挫败 |
| **可理解的语境** | 表达块绑定语境而非孤立 | 每条都带"雅思写作/口语场景"例句 |

### 4.3 弹出节奏与防打扰

- **弹出间隔**：默认每 X 分钟弹 1 条（可调，如 5–20 min）。
- **停留时长**：默认 M 秒（可调）。
- **位置**：屏幕四角可选（默认右下角），避开任务栏。
- **智能避让**（可选增强）：全屏游戏/演示时暂停弹出或降低频率；失焦/锁屏不弹。
- **每日上限**：可设每日最多弹出条数，避免疲劳。

### 4.4 自评按钮与调度的映射（SM-2 变体）

| 评分 | 含义 | 对下次间隔的影响（示例策略，可调） |
|------|------|----------------------------------|
| 😵 忘了 | 完全不记得 | 重置为短间隔（如 10 min / 当天重现），easiness 下调 |
| 🤔 有点印象 | 模糊记得 | 间隔 ×较小系数（如 ×1.2） |
| 😎 记得 | 轻松记得 | 间隔 ×较大系数（如 ×2.5），easiness 上调 |

> 说明：采用**成熟、简单的 SM-2 变体**，不追求 Anki 级复杂算法；调度参数全部可调。

## 5. 数据模型（本地存储）

使用 **SQLite**（随 Electron 本地存储，零外部依赖、便于备份，且符合"自用+可上传 GitHub"的轻量诉求）。

### 5.1 表达块表 `expressions`

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 主键 |
| plain | TEXT | 普通词（如 `important`） |
| advanced | TEXT | 高级表达（如 `plays a pivotal role in`） |
| example | TEXT | 雅思语境例句 |
| topic | TEXT | 话题标签（教育/科技/环境…，可选） |
| source | TEXT | 来源（内置 / 手动新增 / 截图 / AI，V2 用） |
| created_at | INTEGER | 创建时间 |

### 5.2 记忆调度表 `srs_state`（与 expressions 一对一）

| 字段 | 类型 | 说明 |
|------|------|------|
| expr_id | INTEGER PK/FK | 关联表达块 |
| easiness | REAL | SM-2 难度系数（默认 2.5） |
| interval | REAL | 当前间隔（分钟） |
| repetitions | INTEGER | 连续答对次数 |
| due_at | INTEGER | 下次应弹出时间戳 |
| last_reviewed | INTEGER | 上次复习时间 |

### 5.3 设置表 `settings`（键值）

| 键 | 说明 |
|----|------|
| popup_interval_min | 弹出间隔（分钟） |
| popup_stay_sec | 停留时长（秒） |
| recall_delay_sec | 阶段A"先显示普通词"的回想时长 |
| popup_position | 弹出位置（四角） |
| sound_enabled | 音效开关 |
| sound_volume | 音量 |
| sound_file | 自定义音频文件路径（预留接入点，用户自放音频） |
| daily_cap | 每日弹出上限 |
| ai_provider / ai_api_key / ai_base_url / ai_model | **V2 预留**：AI 配置（DeepSeek/Kimi 可切换） |

> **音效说明**：本次只预留 `sound_file` 接入口与默认音效，具体音频由用户后续自行放置，不在本期敲定。

## 6. 技术架构

### 6.1 技术栈

- **语言**：TypeScript
- **桌面框架**：Electron（主进程 + 渲染进程）
- **前端**：React + Tailwind CSS（精美 UI，毛玻璃/排版/间距）
- **存储**：SQLite（`better-sqlite3`，同步 API，简单可靠）
- **构建**：electron-vite 或 electron-forge（Vite 生态，开发体验好）
- **AI（V2）**：可切换 provider（DeepSeek / Kimi），OpenAI 兼容接口，用户自配 API Key

### 6.2 进程结构（Electron 标准）

```
┌─ Main Process（主进程，Node）
│   ├─ 窗口管理：创建/控制"弹窗窗口"与"管理界面窗口"
│   ├─ 调度器：SRS 计时、到点触发弹出
│   ├─ 数据层：better-sqlite3 读写（expressions / srs_state / settings）
│   ├─ 系统能力：托盘、开机自启、全局快捷键(V2)、音效播放
│   └─ IPC 服务：向渲染进程暴露数据与设置接口
│
└─ Renderer Process（渲染进程，Chromium）
    ├─ 弹窗 UI（React 卡片：普通词 → 高级表达 → 自评按钮）
    └─ 管理界面 UI（表达库 CRUD + 设置面板）
```

- **弹窗窗口**：`alwaysOnTop`、`frameless`、`transparent`、`skipTaskbar`，可拖动。
- **通信**：主进程 ↔ 渲染进程走 `ipcMain`/`ipcRenderer`（contextBridge 安全暴露）。

### 6.3 目录结构（建议）

```
Tasymize/
├─ docs/superpowers/specs/          # 设计稿（本文件）
├─ src/
│  ├─ main/                         # 主进程
│  │  ├─ index.ts                   # 入口、窗口创建、生命周期
│  │  ├─ scheduler.ts               # SRS 调度器
│  │  ├─ db.ts                      # SQLite 数据层
│  │  ├─ srs.ts                     # SM-2 变体算法
│  │  └─ ipc.ts                     # IPC 接口注册
│  ├─ preload/                      # 预加载（contextBridge）
│  │  └─ index.ts
│  └─ renderer/                     # 渲染进程（React）
│     ├─ popup/                     # 弹窗 UI
│     │  ├─ PopupCard.tsx
│     │  └─ popup.html
│     └─ manager/                   # 管理界面 UI
│        ├─ App.tsx
│        ├─ views/                  # 表达库 / 设置
│        └─ index.html
├─ assets/
│  └─ sounds/                       # 音效（含用户自定义接入口）
├─ data/                            # 内置初始表达块（JSON，首次导入 SQLite）
├─ package.json
├─ tsconfig.json
└─ README.md
```

## 7. UI / 视觉设计要点

- **弹窗卡片**：毛玻璃（backdrop-blur）+ 半透明深色底 + 圆角 + 柔和阴影；滑入/淡出动画。
- **排版**：普通词（中性色）→ 高级表达（高亮主色，视觉焦点）→ 例句（次要、较小）。
- **自评按钮**：三个表情化按钮，键盘 1/2/3 也可触发（便于快速操作）。
- **管理界面**：左侧导航（表达库 / 设置），右侧内容；简洁高级，留白充分。
- **整体调性**：极简、高级、不吵。

## 8. 错误处理与边界

- **数据库初始化失败**：首次启动自动建表 + 导入内置表达块；失败时托盘提示并写入日志。
- **无到期内容**：调度器空闲等待，不报错。
- **音效文件缺失**：静默降级（不播，不崩溃）。
- **多屏 / 分辨率变化**：按主屏 + 选定角落重新定位。
- **AI 未配置（V2）**：相关功能置灰并提示"请先配置 API Key"。

---

## 9. 测试策略（V1）

- **单元测试**：`srs.ts`（SM-2 变体的间隔/easiness 计算）、`db.ts`（CRUD 与调度查询）。
- **手动验收**：
  1. 启动后按设定间隔在右下角弹出卡片并有音效。
  2. 点"忘了/有点印象/记得"能改变下次弹出时间（可在管理界面看到 due 变化）。
  3. 不点则超时自动消失。
  4. 管理界面可增删改表达块，立即参与调度。
  5. 设置（间隔/时长/音量/开关）改动即时生效。

## 10. 非目标（Non-Goals，本期明确不做）

- ❌ 复杂的 Anki 级算法。
- ❌ 花哨动效与复杂交互。
- ❌ V2 的截图翻译与句子升级的具体实现（本期仅预留接口与配置项）。
