# 设计：雅思词书 + 学习队列轮回机制（V2 核心）

> 日期：2026-07-23
> 背景：V1.1 完成后，用户对"一锅轮"机制提出质疑（50 词无序轮转、无学习节奏），并提出词书需求。经 brainstorming 定案。本设计取代原"按主题生成词组"的思路。
> 核心两件事：① **学习队列轮回机制**（解决轮回混乱）② **词书**（解决词从哪来）。两者通过 `status` 字段缝合。

## 一、用户决策记录（已确认）

| 决策点 | 结论 |
|---|---|
| 词书的词从哪来 | **AI 自编词表**（我用知识生成高频词，不照搬受版权词表） |
| 词义/例句何时生成 | **预生成内置**（离线批量生成打包进 App，用户零 API 消耗） |
| 选书后词如何进入背诵 | 不强制一本本背；词书是"往词库添词的一种方式" |
| 学习队列节奏 | **容量上限制**（同时在学的词有上限，毕业一个补一个） |
| 难词多久再见 | **忘了 5 分钟内再见**（死磕难词） |
| 弹性数值 | **全部开放在设置里改 + 提供"恢复默认"按钮** |

## 二、核心概念：词的生命周期（status）

每个词增加 `status` 字段，三态轮转：

```
new（新词，未解锁）
  │  学习队列有空位时补入
  ▼
learning（学习中——"轮回分界线内"，反复弹）
  │  连续答对 pass_count 次 → 毕业
  ▼
review（复习——分界线外，按天数间隔回炉）
  │  复习时点"忘了"
  ▼
打回 learning（重新学）
```

- **new**：词书里还没解锁的词 / 手动新加的词。**不会被弹窗**。
- **learning**：学习队列里的词，是弹窗的主要来源。
- **review**：已毕业，到期（按天）才回队列露脸。

## 三、学习队列（容量上限制）

- 容量上限 `learning_cap`（默认 10，设置可调）
- 引擎只在「learning 到期」+「review 到期」里挑弹窗对象；new 永不弹出
- learning 中某词毕业（→review）空出位置 → 从 new 补一个词进 learning
  - 补位优先级：当前激活词书的 new 词 → 手动添加的 new 词
- 效果：同时面对的永远是 ≤ learning_cap 个词，学会一个才来一个新的

## 四、评分语义（SRS 改造）

| 点击 | 在 learning 队列 | 在 review 状态 |
|---|---|---|
| 😵忘了(0) | 连续计数清零，**5 分钟后**再见 | **打回 learning**，连续清零，5 分钟后 |
| 🤔模糊(1) | 连续计数清零，**20 分钟后**再见 | 间隔×1.2，保持 review |
| 😎认识(2) | 连续+1；满 pass_count 次 → **毕业进 review**（首个 review 间隔 1 天） | 间隔按阶梯推进 |

### review 间隔阶梯（艾宾浩斯）
`1天 → 3天 → 7天 → 15天 → 30天`（分钟：1440/4320/10080/21600/43200）
毕业词第 1 天回炉，记得→3 天→7 天→15 天→30 天（基本掌握）。

### learning 队列内"认识"的递进
`10分钟 → 60分钟 → 满 N 次毕业`（确保不是碰巧记住）

## 五、弹性数值（设置项，均可调 + 恢复默认）

| 设置键 | 默认 | 含义 |
|---|---|---|
| `learning_cap` | `10` | 学习队列容量（同时在学的词数） |
| `pass_count` | `3` | 毕业所需连续答对次数（已有） |
| `forgot_gap_min` | `5` | 点"忘了"后多久再见（分钟） |
| `fuzzy_gap_min` | `20` | 点"模糊"后多久再见（分钟） |
| `learning_step_min` | `10,60` | learning 内"认识"递进间隔（分钟，逗号分隔） |
| `review_steps_day` | `1,3,7,15,30` | review 间隔阶梯（天，逗号分隔） |

**恢复默认**：设置页顶部加"恢复默认设置"按钮，点击后所有弹性数值重置为上表默认值（带二次确认，防误触）。

## 六、词书功能

- 我用 AI 自编 2-3 本词表（如《雅思核心高频》《学术写作必备》《听力同义替换》），预生成 word+meaning+example+topic，存 `data/wordbooks/*.json` 打包进 App
- 管理界面新增"词书"页：列出各词书（名称/词数/简介），点"加入学习计划"
  - 加入 = 这本书的词**以 new 状态**批量入词库（不立即弹出，靠第三节补位机制逐个进 learning）
  - 已加入的词书标记"已加入"，可移除（移除=删除该书 source 标记的、仍处 new 的词；learning/review 中的不动）
- 保留"自由输入加词"：手动敲一个词 → AI 补 meaning/example → 以 new 状态入库
- `VocabItem` 增加 `book` 字段（词书 id，手动/种子词为 null），用于词书来源追踪与移除

## 七、数据模型变更

```ts
VocabItem {
  id, word, meaning, example, topic,
  book: string | null,        // 新增：来源词书 id
  status: 'new' | 'learning' | 'review',  // 新增：生命周期
  source, created_at
}
```
- 现有 50 个种子词迁移：状态置为 `learning`（保持现状继续背）
- SRS 状态沿用现有 SrsState（easiness/interval/repetitions/due_at/last_reviewed），review 阶梯通过 interval 实现

## 八、界面变更

- 管理界面新增"词书"标签页（生词库/词书/设置 三页）
- 生词库列表显示每个词的 status（新词/学习中/复习中）
- 设置页新增"记忆节奏"分区：上述弹性数值 + 恢复默认按钮

## 九、明确不做（YAGNI）

- 不做"每日固定新词任务"（用容量上限替代，更柔性）
- 不做多本词书并行学习的复杂调度（词书只是添词来源，进了 new 就统一排队）
- 不做 AI 按主题生成词组（已被词书方案取代；自由输入补词保留）
- 不做词书在线下载/导入外部词表（本期只用内置自编词表）

## 十、测试重点

- status 状态机：new→learning→review 各流转正确，忘了打回
- 学习队列补位：毕业后从 new 正确补词、不超过 learning_cap
- 评分语义：忘了 5 分钟/模糊 20 分钟/毕业进 review/复习忘了打回
- 词书：加入→new 入库、移除只删 new、不污染 learning/review
- 恢复默认：一键重置所有弹性数值
