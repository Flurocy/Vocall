# 设计修订：弹窗节拍队列调度模型（取代绝对时间模型）

> 日期：2026-07-24
> 触发：用户洞察——"除了弹窗出现的间隔以外，本质上都是对队列的操作；你不知道过去了多少天，也没有总体 timer"。用户提出调度模型应从"绝对时间"改为"弹窗节拍队列"。
> 本文档修订 `2026-07-23-wordbook-learning-queue-design.md` 的第三/四节（SRS 与调度部分）。

## 一、为什么改（用户的核心洞察）

旧模型用**绝对时间戳**（due_at = 某个时间点，间隔按分钟/天计）。在碎片弹窗场景下失真：

- "忘了 5 分钟后再弹"——但弹窗间隔是 8 分钟，根本没有一个弹窗点落在 5 分钟，所谓 5 分钟是虚的，实际等下一个弹窗点。
- "复习间隔 1 天"——用户两天没开电脑，"1 天"到了也没人弹；一开机一堆"过期词"全挤在一起。
- 没有总体 timer，系统不知道"过了几天"。

**结论：弹窗本身就是一个离散的节拍器。词该什么时候出现，该用"第几次弹窗"来衡量，而不是"几点几分"。**

## 二、权重排序方案的评审（用户提出，被否）

用户曾提出"每个词按用户决策改权重排序"。评审后否定，理由：
1. **黑箱**：权重分数不直观（"权重 87"意味着什么？），队列位置才直观（"排第 3 位，再弹 2 个就到"）。
2. **调参黑洞**：忘了 +10 还是 +20、衰减多少，参数互相影响难调；队列插入位置是确定性的。
3. **解决不了复习**：毕业词要隔很久回来，权重得随时间回升——又回到时间了，正是要摆脱的东西。
4. **毁可视化**：权重是连续谱画不出"学习中/待学习"分界线。

**保留用户的核心诉求**（不同词弹出频率有差异、且用户可调），用"队列插入位置 + 可调插位"实现：忘了插得近（高频）、认识插得远（低频）、插位数值开放设置。

## 三、新模型：弹窗节拍队列

### 核心：全局节拍计数器
- store 增加 `popCount: number`——弹窗弹一次 +1。这是唯一的"时钟"。
- 每个词的 SRS 状态记 `duePop: number`——"第几次弹窗时该出现"。
- **到期判定**：`duePop <= popCount` 即到期（取代了 `due_at <= now`）。

### learning（学习中）
弹窗主要来源。评分操作（插位数值均可设置）：
- 😵忘了 → 连续清零，插到 `popCount + forgot_gap_pops`（默认 3，即"再过 3 次弹窗回来"）
- 🤔模糊 → 连续清零，插到 `popCount + fuzzy_gap_pops`（默认 8）
- 😎认识 → 连续+1，按 `learning_step_pops`（默认 `1,2`，即第1次认识过1次、第2次过2次再弹）递进；满 `pass_count` 次 → 毕业进 review

### review（复习）
不进日常队列。毕业时记 `duePop = popCount + 首个复习间隔`。
- 😎认识 → 按 `review_steps_pops` 阶梯推进（默认 `80,240,560,1200,2400`，大致对应原 1/3/7/15/30 天按典型弹窗频率折算），封顶
- 🤔模糊 → 间隔×1.2，保持 review
- 😵忘了 → 打回 learning（连续清零，按忘了插位）

> 复习阶梯单位是"弹窗次数"。默认值按"每天弹 ~80 次"折算：1天≈80次、3天≈240次……用户可在设置里按自己的使用频率调。

### 补位（不变，仅时机补全）
- learning 不足 `learning_cap` 时从 new 按 id 升序补，新补词 `duePop = popCount`（立即可弹）。
- **补位时机（修 bug）**：启动时、毕业时、**词书加词后**都调用（原来漏了加词后，导致队列空了不补位）。

## 四、可视化（用户建议）
主页面生词库画一条**分界线**：线上是"学习中"（会被弹），线下是"待学习"（new，排队中）。一眼看懂学习队列机制。

## 五、数据模型变更

```
SrsState { easiness, repetitions, duePop }  // interval(分钟)→duePop(节拍数)，删 due_at/last_reviewed
store 增加 popCount: number
```
- 迁移：旧 `interval/due_at` 一律重置为 `duePop = 当前 popCount`（立即可弹）——旧时间数据无法精确换算，且立即复习无害。popCount 初始 0。
- 状态机 status（new/learning/review）不变。

## 六、设置键变更（弹性数值）

| 旧键 | 新键 | 默认 | 单位 |
|---|---|---|---|
| forgot_gap_min=5 | forgot_gap_pops | 3 | 弹窗次数 |
| fuzzy_gap_min=20 | fuzzy_gap_pops | 8 | 弹窗次数 |
| learning_step_min='10,60' | learning_step_pops | '1,2' | 弹窗次数 |
| review_steps_day='1,3,7,15,30' | review_steps_pops | '80,240,560,1200,2400' | 弹窗次数 |
| learning_cap=10 | （不变） | 10 | 个 |
| pass_count=3 | （不变） | 3 | 次 |
| popup_interval_min | （不变，这是真实墙钟） | 8 | 分钟 |

## 七、不变的部分
词书批量勾选加入、status 三态语义、学习队列容量制、毕业补位机制、弹窗交互（翻卡/自评/拖拽）、主题/设置 UI 框架。只换"何时弹哪个词"的调度依据。

## 八、测试重点
- popCount 递增、duePop<=popCount 到期判定
- 忘了/模糊/认识的插位（按 popCount 算）
- 毕业 duePop 进入首个复习间隔、复习忘了打回
- 复习阶梯按弹窗次数推进、封顶
- 补位三时机（启动/毕业/加词后）
- 迁移：旧数据 duePop 重置
