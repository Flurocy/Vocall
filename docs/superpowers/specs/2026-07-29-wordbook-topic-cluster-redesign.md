# 词书生成脚本：按话题聚类 + 穷举式重新设计

日期：2026-07-29
分支：feat/v1-popup-tray
基线：scripts/gen-wordbook.mjs 当前工作区状态（含包2 初版 + 真跑热修：重试/JSON截断容错/小批量补生成/max_tokens 调整）
关联：docs/superpowers/plans/2026-07-28-wordbook-gen-and-dup-guard.md（功能二脚本初版）

## Context（为什么重新设计）

词书生成脚本初版（按"考试场景"切分：真题高频/听说场景/读写学术/同义替换/高分进阶）真跑暴露严重问题：
第一本 1200 词满，**第二本只剩 429、第三本只剩 154**（目标均 800）。

根因有二：
1. **雅思实用词库总量有限**（约 5000–7000 词），场景式切分天然重叠。
2. **前三本主题高度同质**（本质上都是"雅思通用学术词"），第一本把池子里最通用的词全占走，后面去重后无词可挑——这是数学必然，调 prompt/token 治不好。
   （第四本"同义替换"700 满、第五本"高分进阶"497 近满，恰恰因方向更独立，反向印证根因。）

此外用户提出新需求：**生成的词应按词义/词根聚类排列（利联想记忆），而非字母顺序**。

用户决策（2026-07-29）：
- **改按话题聚类**（话题天然互斥，治本；话题内天然聚类，顺带满足排列需求）。
- **不设硬性词量目标**——每本该挖多少挖多少（穷举），总量预计 ~3000。

## 设计

### 1. 五本话题分配（互斥 + 隐含难度递进）

| 本 | id | name | 覆盖话题 | 对应考试 | 难度 |
|---|---|---|---|---|---|
| 1 | ielts-daily | 居家出行 | 住房/交通/饮食/购物/旅游/银行 | 听力 S1-2 | 基础 |
| 2 | ielts-campus | 校园健康 | 教育/课程/学习/医疗/运动 | 听力 S3 + 口语 | ↓ |
| 3 | ielts-society | 社会文娱 | 家庭/人口/社会问题/文化/媒体/艺术/体育 | 口语 + 写作 | ↓ |
| 4 | ielts-tech-env | 科技环境 | 科技/互联网/环境/气候/能源/动物 | 写作高频 | ↓ |
| 5 | ielts-public | 政经法理 | 政府/法律/犯罪/经济/商业/工作/抽象评价词 | 议论文 + 7+进阶 | 最高 |

- 话题**互斥**（"环境"的词不进"教育"那本）→ 不再"前一本吃掉后一本"。
- 全局去重 Set **保留**作兜底（AI 偶尔把同一词归进多个话题，如 pollution∈环境/社会，全局 Set 拦住）。
- 预计总量 ~3000（每本 500–800，视话题自然产出）。

### 2. 生成哲学：穷举而非凑数

替换初版"目标 count + 补生成到目标"的死指标逻辑：
- 每本：针对它的话题清单，分批让 AI 挖词，**挖到自然枯竭**——连续 N 批（N=2）新增 < 5 个词即认定该话题池挖尽，停止。
- 不再追求固定词数；每本落盘实际产出数。
- 治好初版的"补生成词穷"（让 AI 一次憋几百个不重复词导致 max_tokens 截断/content 为空）。

### 3. 聚类排列（满足联想记忆需求）

- 阶段1 prompt 明确要求：**同话题内按词根/同义族相关排列**（示例：debate / argue / discuss / controversy / dissent 挨在一起），小写、JSON 字符串数组。
- 词表落盘（.wordlist.json）即带此聚类顺序；阶段2 配内容时沿用 → 最终词书内相关词天然聚一起。

### 4. 数据流（两阶段，沿用初版架构）

**阶段1（穷举词表 + 聚类）→ scripts/.wordlist.json：**
```
for each book:
  pool = {}
  repeat:
    batch = callAndParse(prompt: 挖该话题词、话题内聚类排列, parseWordArray)
    newCount = pool 新增数
    若连续 2 批 newCount < 5 → break（自然枯竭）
  全局去重分配（assigned Set 兜底，跨本零重复）→ wordlist[book.id]
```

**阶段2（逐词配内容）→ data/wordbooks/<id>.json：**
- 沿用阶段1 词序（聚类顺序），分批（CONTENT_BATCH=15）配 {word, meaning, example, topic}。
- 容错解析、断点续跑（以词书文件为准）、去重兜底、连续失败中止——均不动（初版已验证）。

### 5. 脚本改动点（scripts/gen-wordbook.mjs，相对当前工作区）

- `BOOKS` 定义：5 本 id/name/desc 全换为话题版（见上表）；`topicHint` 字符串 → `topics` 话题清单；**移除 `count` 字段**（穷举哲学不设目标值；日志直接打实际产出数，不需预估）。
- `genWordlist(book, assigned)`：删"need=count×1.2 + 补生成到 count"逻辑，改"穷举循环 + 连续2批<5停止"。
- `WORDLIST_SYSTEM` prompt：加"话题内按词根/同义族聚类排列"要求 + 话题清单注入。
- 穷举停止阈值常量：新增 `EXHAUST_NEW_THRESHOLD = 5`、`EXHAUST_BATCHES = 2`。
- 不动：callDeepseek、callAndParse（重试+调试输出）、extractJsonArray（截断容错）、阶段2 全流程、断点文件、CLI、key 安全。

### 6. 错误处理

- 沿用：单批失败内层重试 2 次（阶段2）/ 3 次（阶段1）；401/402 致命错误不重试直抛；JSON 截断容错（缺 `]` 退到最后完整元素）；连续 3 批失败中止（阶段2）；断点续跑。
- 穷举循环加防护：每本最多跑 M 批（如 30）防 AI 一直吐重复词导致死循环（理论上枯竭判定会先触发，M 是兜底）。

### 7. 测试影响

- 脚本本身无单测（一次性工具，计划既定）。
- 词书成品被 tests/wordbook.test.ts、wordbook-batch.test.ts、vocab-dup.test.ts 加载——这些测试只依赖"存在某本词书 + 词书结构正确 + 去重逻辑"，**不依赖具体词数/词序**，不受本改动影响。
- 占位词书 ielts-sample.json：本改造不涉及（仍按 plan I-1 过渡清单，跑脚本前手动删）。

### 8. 不做 / 边界

- 不改包1 同词拦截任何代码。
- 不改阶段2 内容生成逻辑（仅沿用新词序）。
- 不引入新依赖（仍纯 ESM .mjs、Node 内置）。
- 不强求每本词数对齐（穷举哲学的核心）。

## 验证

- `node --check scripts/gen-wordbook.mjs` 语法 OK；`--help` 正常。
- `npm test` 绿（不受影响，确认即可）。
- 真跑（用户挂 key）：
  1. `--only-wordlist`：五本均能穷举到自然停止，无"补生成词穷"中止；每本产出 500–800（合计 ~3000）；抽查 .wordlist.json 词按话题聚类排列。
  2. 抽查词质量：话题归属合理、词根相近词聚一起、无字母序堆砌、跨本无重复。
  3. 满意后跑全量生成 5 本词书 JSON，listWordbooks 能正常加载。
